# コロ作成時の構成とファイル交換

2026-11-14合意。同日に実装した。候補値のうち「検証後に決定」とした項目は仮の値で動かしている（[引き継ぎ](session-handoff.md) を参照）。会話中の「総数」は「層数」として整理する。

## はじめから

「はじめから」でコロを作る際に基本構成を決める。通常は下記の初期値を表示し、そのまま始められる。「詳しい設定」を開くと変更できる。

| 設定 | 初期値 | 利用者向けの説明 |
| --- | ---: | --- |
| 文脈の上限 | 128トークン | 一度に参照できる文章の長さ。トークンは1文字とは限らない |
| 次元数 | 48 | 1トークンを表す数の個数 |
| 層数 | 3 | 情報を加工する段階の数 |
| ヘッド数 | 3 | 各層で、別々に参照先を計算する組の数 |
| 会話の保存上限 | 検証後に決定 | 専用の本に残して読み返せる会話の量 |
| まとまりの登録上限 | 検証後に決定 | 勉強で見つけた複数文字のまとまりを登録できる数。1文字用の枠は別 |

会話の保存上限とまとまりの登録上限も「はじめから」で選び、コトごとに保存する。文脈の上限（1回の計算で参照する範囲）とは別の設定として説明する。具体的な初期値・選択肢・単位は容量と処理時間を検証して決める。上限を選ぶことは、その数の単語を最初から登録することではない。

1文字用と複数文字のまとまり用の枠を分ける。まとまりが満杯でも、それを理由に初見の文字の登録を止めない。文字と制御用記号は、利用者が選んだまとまりの上限へ算入しない。番号は既存の対応を維持し、枠の分類のために振り直さない。文字側にも容量上の制約は必要だが、無制限という約束にはせず、具体的な制約・到達時の処理は実装時に検証する。

大きくすると計算量や保存容量が増えることを説明する。必ず賢くなる、各成分・ヘッドが決まった意味を持つ、とは説明しない。

自由な数値入力ではなく、検証済みの組み合わせから選択する。次元数はヘッド数で割り切れる必要がある。各項目を選ぶと、組み合わせとして未検証・不成立になる選択肢を無効にする。個々の値を別構成で検証しただけで、その全組み合わせを検証済みとしない。

独立検証済みの構成は128／48／3／3と256／96／3／3（文脈／次元／層／ヘッド）。後者の測定では語彙容量も2048で、前者の1024とは異なる。層数・ヘッド数を変更するための選択肢は、追加検証後に確定する。PCでの計算検証と、ゲーム統合・スマホ実機の確認は区別する。[測定条件と結果](benchmark-results.md)

## 作成後の扱い

- 構成は人やアプリ全体ではなく、そのコロの保存データに属する。
- 次元数・層数・ヘッド数・文脈上限は作成後に通常設定から変更しない。構成を変えて試す場合は、新しいコロとして初期化する。既存の重みを別形状へ無断で変換しない。
- 「続きから」とファイル読込では、保存された構成を復元する。現在の画面の初期値や別のコロの設定を上書き適用しない。
- 同じ人が異なる構成のコロを扱ってもよい。ただし複数セーブを管理する画面の実装範囲は別途決める。
- 実際に読む範囲を作成時の文脈上限より短くすることは可能。ただし今回、日常設定の画面を追加するところまでは確定しない。
- まとまりの登録上限は作成画面で選ぶが、登録する単語や区切り方を選ぶ設定にはしない。1文字から始め、既成の単語一覧を与えず、以下の勉強でまとまりを追加する。既存の番号と重みの対応は維持する。

## 机で「ことばのまとまり探し」

部屋の既存の観察ノート用の机を使う。机上のノートを押すと従来の観察ノート、追加する勉強用の本を押すと「ことばのまとまり探し」を開始する。机全体のクリックで観察と勉強の両方を起動しない。ゲーム内の週次自動実行や別キャラの訪問案は採用しない。

コト自身が本で勉強を始め、頭の中へ移って、集まったお手本によく出る文字の並びを調べる。元のカードを並べ、新しいまとまりを登録し、対応する原本の欄を追加する。既存の机は `blender/build_assets.py` の `journal_desk`、観察の入口は `src/ui/stage.js` の `journal`。現時点では勉強用の本・処理は未実装。

専用の本に作成時に選んだ上限まで過去の会話を保存し、勉強では今その本に残っている会話を読み返す。上限を超えたら古い会話から外すが、獲得済みのまとまりと学習済みの重みは消さない。まとまりの登録上限に達したら、新しいまとまりの追加を止め、既存の登録を勝手に消さない。文字は別枠で登録する。

開始できるのは、普段コトと自由に会話できる状態のとき。勉強中は会話や別の作業を開始せず、終了後に通常の会話できる状態へ戻る。特定の曜日・時刻を待つ必要はない。

- 画面でも計算でも1文字単位から始める。初めて見る文字にはその都度新しい番号と対応する欄を追加する。制御用の記号は別に持つ。既成の複数文字語彙は与えず、バイト単位からの勉強にはしない。結合文字・絵文字の「1文字」の境界や、文字側の容量制約到達時の扱いは実装時に整合させ、原文を失わない。
- 対応表は消さずに追加する。既存のトークン番号、文字列、結合規則、学習済みの重みを保持する。全体の初期化や一からの学習し直しは行わない。
- 新しいまとまりへ新しい番号を付ける。入力の埋め込みと出力の候補の両方で、その番号を扱えるようにする。単に対応表だけへ追加して終わらせない。
- 「意味を覚えた」ではなく「よく出る文字の並びをひとまとまりで読めるようにした」と説明する。必ずしも辞書にある単語ではない。使い方は以後の通常の学習で育つ。
- 追加できるまとまりがなければ、その結果を伝えて終了する。押すたびに無理に追加しない。
- 勉強の終了時に「今回見つけたまとまり」と、その元になった本の会話を示す。新しいまとまりがない場合も明示する。まとまりの登録上限によって追加できない場合は、見つからなかった場合と区別する。
- 同じ教材内で繰り返し現れる文字の並びを候補にし、1回の勉強で少しずつ追加する。具体的な出現回数のしきい値・一度の追加数は検証して決める。ボタンを押し直した回数を、教材内での出現回数として加算しない。既に登録したまとまりを重複登録しない。
- 既存の番号を保持しても、新規の結合によって同じ文章の区切り方・長さは変わり得る。以前と全く同じ返答を保証しない。
- 保存には追加後の語彙・結合規則と対応する重みをセットで含める。更新途中の対応表だけを保存しない。
- 中断・アプリ終了時にも、対応表と原本の整合性を保つ。新しい一組の保存が完了するまでは、直前の整合した保存を保持する。再開時は完了済みの一組を復元し、同じ追加を二重に適用しない。保存の具体的な方式は実装側で設計・検証する。

追加方式は目標仕様。当初の速度ベンチマークは先に語彙を作って固定する方式であり、その測定だけでは育成途中の追加の検証にならない。「本に残っている会話から繰り返し現れる並びを候補にして少しずつ追加する」方針は合意済み。上限の具体的な選択肢、出現回数のしきい値・候補の優先順位・一度の追加数、新しい重みの初期化は今後の精査対象。実LLM一般が利用中に自動で語彙を増やす、と説明しない。

後続の明示依頼で[育成途中の追加検証](vocabulary-growth-results.md)を実施。小規模の3乱数種×3方式で、旧番号・重み保持、追加後の継続学習、保存復元、2回目の追加を確認した。ただし全条件で追加直後の誤差は増えた。構成元の平均による初期化は次の候補であり未確定。長期・大語彙・会話品質・ゲーム統合は未検証。通常学習と別に自動で慣らし学習する仕様は追加していない。

ユーザーは会話品質を重視せず、追加直後の返事の変化は許容する方針。品質維持のためだけの追加確認を実装の前提にしない。番号・重みの保持、計算の成立、保存の整合性は引き続き必要。

## 教材にする文章

ユーザーが教えた会話と、ファイルで招いた相手の返事を教材として残す。コト自身が生成した返事は、自動で正解として学習しない。この区別を通常の学習と、机でのまとまり探しの両方へ適用する。

- 教材には元の文章と発話順序・発話者・出所を保持する。語彙追加後も再度トークン化できるよう、番号列だけを教材の原本にしない。
- ユーザーが教えた会話のお手本では、複数の役の発話も教材にできる。「コト役の発話」と「コト自身がその場で生成した発話」は出所で区別する。
- 自分の返事を、相手の次の返事を理解するための文脈として参照することは、正解として学習することとは別。文脈に含める場合も、自分の返事の位置を正解の予測対象から除外する。文脈経由の勾配まで一律に止める意味ではない。
- まとまり探しでは、自動生成した自分の返事を出現回数の集計へ自動で加えない。
- 招いた相手の返事を教材にすることは、その内容の正しさを保証しない。会話から必ず品質が向上するとは説明しない。

専用の本には会話の流れとしてコト自身の返事も記録できるが、正解・まとまり探しの対象と区別する。保存は上限つきで古い会話から外す。具体的な上限、ユーザーが教材を確認・修正する導線、交換ファイルに会話記録まで含めるかは未確定。

## ファイルで相手を招く将来機能

相手のコロのファイルを受け取った人が自分のアプリへ読み込み、自分のコロと相手のコロを会話させる。その会話を教材に、自分のコロが通常の学習を行う。相手の重みを自分の重みに混ぜる機能ではない。

- 相手は読み込んだ重みで返事を生成し、自分のコロの原本を学習で更新する。送り主のアプリへ更新は戻らない。
- コロ同士は文章でやり取りし、それぞれ自分のトークナイザーで数へ変換する。次元数・層数・ヘッド数・語彙が同一である必要はない。相手のトークン番号をそのまま自分へ渡さない。
- ファイルには形式の版、モデル構成、トークンと文字列の対応・分割規則、学習済み重みを一式含める。番号の対応表だけを別のものに差し替えない。
- 読込側がその構成と計算方式に対応している必要がある。非対応形式や不正な形状は、現在のコロを置き換える前に説明して読込を中止する。
- でたらめな返事も教材になる。会話や学習で必ず品質が向上するとは扱わない。

アプリ間の直接通信、送り主への同期、重みの合体は今回の対象外。ファイル交換機能の具体的な画面・実装時期は今後整理する。

## 実装再開後の受け入れ条件

1. 初期値で開始でき、詳しい設定には検証済みで成立する組み合わせだけが表示される。
2. 選んだ構成が実計算・本やバインダーの説明・保存内容に一致する。12次元や1層などの固定表示を残さない。
3. 保存して読み直すと構成と予測が復元され、別の新規作成設定に影響されない。
4. 新規作成時の初期化と、既存のコロの継続を区別する。構成変更だけで育てた重みが黙って消えない。
5. 将来の交換機能では、異なる構成・語彙の相手との文章の受け渡し、自分だけの学習、非対応ファイルで既存データを壊さないことを検証する。
6. ノートと勉強用の本の操作が分かれ、本を押したときだけまとまり探しが始まる。週次の自動起動はしない。
7. 語彙追加の直前直後で既存の番号・重みが保たれ、新規番号を入力・予測・通常学習に使える。保存復元、追加なしの場合、繰り返し操作での重複登録も確認する。
8. 教材の出所を保存復元しても保持する。自分の生成した返事を通常学習の正解やまとまり探しの集計へ自動で混ぜず、必要な会話文脈は保持できる。
9. 会話できる状態からだけ勉強を開始し、勉強中に会話・別作業を同時実行しない。完了後は通常状態へ戻る。本の保存上限で古い記録が外れても、既存語彙と育てた重みは保持する。
10. 「はじめから」で会話保存・まとまり登録それぞれの上限を選べ、保存復元で維持される。文脈上限と混同せず、まとまり満杯時に既存の登録を削除しない。満杯の状態でも、別枠の初見文字を登録・学習・保存復元できることを確認する。
11. 勉強結果に新規のまとまりと元の会話を表示し、追加なし・上限到達も説明する。保存前後の中断から復元しても、対応表と重みが食い違わず重複追加も起こらない。
