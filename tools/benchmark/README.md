# 独立したサイズ検証

育成途中の語彙追加の追加検証: `node tools/benchmark/growth.mjs`。Node.js上で3乱数種×3初期化方式を試す。結果は`results/growth.json`、条件・解釈は`docs/vocabulary-growth-results.md`。ゲームからは使用しない。

ゲームからは読み込まない。実装停止中に、ユーザーの「まず、検証して」に対応して作成した試作。

実行: `node tools/benchmark/browser.mjs`（Node 22以降、Windows Chrome。`CHROME`環境変数で実行ファイルを変更可能）。localhostの8782とChromeの9342を使う。結果は`results/browser.json`へ保存する。Chrome用の一時プロファイルはOSの一時ディレクトリに作成する。

勾配検査だけ: `node --input-type=module -e "import {validate} from './tools/benchmark/run.mjs'; console.log(validate());"`

## 検証対象

- 3層・3ヘッドの因果自己注意、残差、固定スケールRMSNorm、GELU、幅2dのMLP、学習する位置埋め込み、独立した入力／出力表。
- 次トークンの交差エントロピーと全層への逆伝播。系列内の損失を平均し、SGD・全体勾配クリップ1で更新する。
- UTF-8バイトから作る小さなBPE。複数文字トークンと未知の文字列の往復を確認。学習後の語彙と結合規則を固定する。
- Float32重み、設定、語彙、結合規則のバイナリ保存・復元。復元後の予測確率が完全一致することを確認する。
- 微小モデルの全22パラメータ群から各3要素、計66要素の有限差分検算。全層の因果性、学習による損失低下を確認する。

## 時間の読み方

学習例は`run.mjs`内の日本語の短い20往復。各往復を1系列とし12周（240更新）。ユーザー文も含めて各位置の次トークンを学ぶ。既存ゲームの1位置ずつ更新する方式とは異なるため、現在のゲームそのものの速度測定ではない。

フル文脈の測定には合成トークン列を使う。学習・1回の推論は5回の中央値、30トークン生成は3回の中央値。生成は毎回フル文脈で再計算し、KVキャッシュなし。実語彙に使われない出力欄も含めて容量1024／2048全体を計算する。これは計算負荷の検査で、生成された文章の品質検査ではない。

CPU上のJavaScript、Web Worker、アニメーションなし。重みはFloat32だが中間値と勾配はFloat64。推論時も学習用の中間領域を確保する未最適化の試作。GPU・WASM・量子化なし。大規模LLMの完全再現や、速度の最適値とは扱わない。

保存形式は検証用。ゲームへの取り込み、外部ファイルの安全な検証・移行、会話画面との接続は未実装。スマートフォン実機、長時間のメモリ推移、会話の成立度は未測定。
