# 本・バインダー方式と育つ語彙の実装設計

2026-11-14。これまでの決定事項を実装可能な単位に整理した設計。同日に第9節の順で実装した。実装で置いた仮の値と設計との差分（Worker 未使用、保存の原子性の範囲など）は [session-handoff.md](session-handoff.md) に記録している。

合意済みの体験・設定は [experience.md](experience.md) と [model-settings.md](model-settings.md) を正とする。本書のデータ名、モジュール分割、保存手順、アルゴリズムの細部は今回の設計案であり、過去の合意や実装済み事項として扱わない。数値の選択肢など検証待ちの項目は末尾にまとめる。

## 1. 全体構成

計算が状態と実測トレースを作り、画面はそれを再生する。再生速度・閲覧・スキップで計算結果を変えない。

```text
家の操作（会話／睡眠／机の勉強）
  → 操作の調停（同時実行を防ぐ）
  → 教材・語彙・Transformerの処理
  → 整合した状態の保存
  → 実トレースによる本・バインダーの演出と結果表示
```

通常の学習とまとまり探しを分ける。睡眠ではお手本の正解から原本の数値を更新する。机の勉強では本の会話からまとまりを探し、対応表と原本の欄を追加する。追加直後の自動的な慣らし学習は行わない。

構成の初期値は文脈128・48次元・3層3ヘッド。MLP幅は独立検証に合わせて2倍の96を設計案とする。構成は作成時に決めて保存し、ロード時には保存値から配列と表示を組み立てる。設定候補は個別値の直積ではなく、検証した組み合わせの一覧で管理する。

## 2. 保存する情報と一時情報

| 区分 | 主な情報 | 維持する条件 |
| --- | --- | --- |
| 構成 `config` | 文脈・次元・層・ヘッド・MLP幅・計算方式の版 | 作成後の通常設定では形状を変更しない |
| 上限 `limits` | 会話保存量・まとまり登録数 | 文字・制御記号はまとまり数へ含めない |
| 語彙 `vocabulary` | ID・文字列・種類・結合規則・規則の順序 | IDは末尾追加のみ。再採番・再利用しない |
| 原本 `parameters` | 入力埋め込み・位置・各層の行列・出力行列とバイアス | 形状と語彙・構成を照合する |
| 会話の本 `conversationBook` | 会話ID・発話順・話者・出所・原文 | トークン番号列を原文の代わりにしない |
| 学習待ち `pendingLessons` | 睡眠で学ぶ会話の原文と対象情報 | 読み返す本の保持期間と学習待ちを混同しない |
| 進行 `progress` | 観察ノート・学習回数・乱数状態・最後の操作結果 | 途中保存から二重適用しない |
| 一時情報 | 計算中間値・トレース・カメラ・閲覧状態 | パラメータや長期記憶として説明しない |

保存単位は `{formatVersion, revision, config, limits, vocabulary, parameters, conversationBook, pendingLessons, progress}` の全体。`revision` は成功した更新ごとに増やす。将来、最適化器に状態を持たせるなら、それも同じ単位に含める。

会話はまとまりごとに保持し、容量超過時は古い会話単位で外す。長い1会話だけで上限を超える場合の制限・案内は容量検証で決め、発話の途中を黙って切らない。学習待ちに入れた会話は本から外れても学習待ち側に必要な原文を保持する。本・学習待ち双方を含む保存量を測る。

発話には `speaker` と `source` を別々に持たせる。例えば `source` はユーザーのお手本、招いた相手、自分の生成文を区別する。コト役として書かれたお手本を、自分の生成文と取り違えない。通常学習の正解対象とまとまり集計の対象は、この出所から一貫して決める。

## 3. 文字とまとまりの対応表

文字、まとまり、制御記号を同じID空間に置き、種類で別枠を管理する。文字用に一定範囲の番号を予約する方式にはせず、必要になった順に末尾へ追加する。

「1文字」の設計候補は書記素単位とする。結合文字や絵文字を途中で割らず、原文を正規化で書き換えない。実装前に対応ブラウザで境界を検証し、分割方式の版を保存する。黙ってコードポイント方式へ切り替えるフォールバックは使わない。各トークンには元の発話IDと文字列の範囲を関連付け、連結すると原文を復元できることを検証する。

初見文字は推論の前処理で登録し、入力埋め込みの行・出力行列の対応列・出力バイアスを同時に増やす。既存の数値はそのままコピーする。これは語彙の準備であり、お手本から重みを学習することとは区別する。**推論で原本を変えないという条件は、文字登録を完了した状態から適用する。** 未知文字を既存の共通IDにまとめて読んだと説明する旧仕様は採用しない。

文字側の容量に達した場合は、原文を欠落させず、処理を開始せずに説明する案とする。具体的な容量と利用者への選択肢は検証後に確定する。

## 4. 机の勉強の処理

1. 通常の会話可能状態で本を押すと、操作を占有し、今残っている会話の本と状態の版を固定する。
2. 対象となる発話を現行の規則で区切る。自分の生成文は集計しない。発話・会話・制御記号をまたぐ結合も作らない。
3. 隣接するトークン対を集計する設計とする。出現箇所には会話ID・発話ID・原文の範囲を残す。
4. 繰り返し条件を満たす未登録の候補を選ぶ。頻度の降順、同数なら既存ID対の昇順という決定的な順序を設計案とする。頻度は今回の教材から再計算し、ボタンを押した回数を足さない。
5. 一つ追加するごとに規則を適用し、候補を再集計する。新しい結合規則には追加順の優先順位を持たせる。同じ文字列の重複登録は行わない。
6. 1回の追加数またはまとまり登録上限で止める。文字の枠は消費しない。
7. 作業用のコピーで語彙と重みを拡張し、旧ID・旧数値・形状・有限値・原文との往復を検査する。
8. 一組の保存に成功してから新状態へ切り替える。成功結果の演出を再生し、最後に通常状態へ戻す。

新規のまとまりの重みは構成元の平均を第一候補とするが、確定ではない。新しい文字は既存の初期化規則に従う。いずれも方式と乱数状態を保持する。語彙追加だけで意味や使い方を学習済みとは表示しない。

結果は「追加したまとまり」「元になった会話」を示す。結果コードは少なくとも追加あり、教材なし、条件を満たす新候補なし、登録上限、保存失敗を区別する。一部追加したあと満杯になった場合は、追加した一覧と上限到達を両方伝える。

同じ本で次回も候補が見つかることは許される。1回の追加数に制限があるためであり、重複追加ではない。処理の重複防止には `operationId` と元の `revision` を使い、同じ完了操作を再適用しない。

## 5. 通常の推論と学習

推論は文字登録→トークン化→直近の文脈窓を選択→順方向計算→出力候補の制約と確率→抽選→文章へ追加、を繰り返す。確率・乱数・選択結果を記録し、演出側では抽選し直さない。最初の統合では窓内を再計算する設計とし、保管したページをKVキャッシュとは呼ばない。

学習は独立検証の系列単位の更新を土台にする設計とする。入力と1位置先の正解を対応させ、因果マスクを使う。自分の生成文の位置は正解対象から除き、文脈としての参照は可能にする。対象位置の損失だけを平均し、対象が0なら更新しない。終端記号の対象可否も元の発話に従わせる。話者を示すためだけの制御記号は予測対象から除外する案とする。

長い会話は文脈上限内の窓へ分け、重ねた文脈部分を二重の正解にしない。各対象位置に元の発話と原文範囲を持たせる。学習率・周回数などは統合検証で確定し、旧モデルの値を新構成に無条件で流用しない。

モデルの仕事を小さな単位で実行できる構造にし、Worker利用を設計案とする。描画スレッドを長時間占有しない。WorkerにはDOM・three.jsを渡さず、操作IDと状態の版を照合して古い結果を捨てる。閲覧のための停止は工程境界で計算の次バッチも止め、すでに生成された結果のバッファは変更しない。

## 6. 3Dの部屋と計算トレース

並べる部屋→①→②〜⑤を層数分→⑥→ルーレット→返事、という依存順序にする。②〜⑤は同じ部屋を巡回し、入室説明と本の閲覧に現在の層を示す。層ごとの原本は別データで、同じ値を複製表示しない。ヘッドは②③の閲覧で切り替える。

| 工程 | 実際に残すもの | 表示上の要点 |
| --- | --- | --- |
| 並べる | 原文範囲、全トークンの順序、窓の範囲 | 窓外は保管として区別し、計算済みの数値を作らない |
| ① | 各位置の埋め込み・位置情報・和 | d個とd個を成分ごとに足してd個になる |
| ②③ | 各層・各位置・各ヘッドのQ/K/Vと注意係数、合成結果 | 見る割合は因果マスク後。未来の位置を参照しない |
| ④ | その層の入力、注意の投影、残差後 | 第2層以降は①の値を直接足さず、その層の入力へ足す |
| ⑤ | 正規化、MLP中間値、出力、2回目の残差 | dとMLP幅を区別し、注意後の値を残差元にする |
| ⑥ | 最終層の値、候補の点、実際の抽選分布 | 入力用と出力用の原本を区別する |
| 学習 | 対象位置、損失、実勾配、更新前後 | 抜粋は抜粋と示し、全更新の表示と偽らない |

トレースの共通項目は `operationId, revision, step, layer, head, position, sourceSpans, parameterRefs` とし、工程ごとの実測値を加える。層・ヘッドが無関係なイベントでは省略する。数値配列は後続の更新で変わらないスナップショットにする。

全入力の対応表は保持する一方、すべての生成ステップの全注意行列を無制限に貯めない。詳細な中間値は現在再生する計算単位に限定し、次へ進んだら解放する。大きい表の閲覧はページ分けする。未収録の数値を架空の値で埋めない。学習表示の単位は「この系列の1更新」などトレースの更新単位と一致させる。

カードは取り出し口から手元へ渡り、束のまま順番に広げられ、①の装置で対応するページへ変わる。キャラクターは机に置く・開く・写す・閉じる・受け取る。学習時には原本を書き直して棚へ戻す。

## 7. アイテム閲覧と停止

`src/ui/items.js` は観察ノートを維持し、勉強結果・バインダー・原本の入口を扱う。大きな数値表やトレースの加工は専用モジュールへ分ける設計とする。机のノートと勉強用の本には別のクリック対象を与える。

右下には今持っているバインダーを表示する。原本は棚から開く。最初に役割を説明し、見開きで基準となる元情報と現在の情報を示す。計算に必要な層入力などは別のページとして参照できるようにする。スマホでは元／現在を切り替えて同じ位置を比較できる配置を設計案とする。数値はタップでも開け、閉じたら元の操作対象へ戻す。

停止は単一の真偽値を上書きせず、`manual`（手動）、`guide`（説明待ち）、`inspect`（閲覧）、`hidden`（非表示）など理由の集合で管理する。閲覧を閉じると `inspect` だけを外す。他の理由が残れば再生しない。説明なし設定でも閲覧中の停止は適用する。

家の状態は通常・推論・睡眠学習・まとまり探し・結果表示に分ける。閲覧はその上に重なる状態とし、閉じても処理の所有者を変えない。勉強開始直後から終了まで会話・睡眠・再度の勉強を受け付けない。スキップは演出の省略であり、状態更新の中断や再計算を意味しない。

## 8. 保存と中断

localStorage方針を維持し、単一の保存キーへ整合した全体を置換する方式を第一案とする。更新前の状態を直接変更せず、次の状態を別に作って検査・直列化してから書き込む。保存成功後にだけメモリ上の正式状態を切り替える。保存失敗を握りつぶす現在の処理は、この要件に合わせて変更する必要がある。

| 中断・失敗した時点 | 復元する状態 |
| --- | --- |
| 集計・拡張中、保存前 | 前回完了した一組。途中の候補を再適用しない |
| 保存が容量不足等で失敗 | 前回の一組を維持。追加成功とは表示しない |
| 保存後、演出・結果表示の途中 | 新しい一組。保存済みの結果を表示し、追加処理は再実行しない |

最後の操作IDと結果要約を新状態へ同梱する。元の会話が後に本から外れても、その結果を復元できるよう、表示に必要な引用範囲を結果へ保存する。引用は最後の結果分だけを保持し、無制限に複製しない。

通常学習は完了した系列更新をチェックポイント候補とし、重み・進捗・乱数・学習待ちの消化位置をまとめて保存する。終了時イベントだけには依存しない。中断した演出の途中フレームは再現せず、保存できた計算境界から再開する。

ロード時には形式、設定の成立、ID一意性、規則の参照、行列形状、有限値、出所、上限を検査する。不正なデータを勝手に空の状態で上書きしない。複数タブからの同時更新はサポートせず、一つだけが書き込める排他方式を統合時に検証する。

旧形式の消去了承は新形式の破損データを黙って消す許可とは区別する。旧方式の整理は実装再開後に実施する。

## 9. 実装する単位と順序

| 順序 | 担当する既存箇所／新設案 | 完了条件 |
| --- | --- | --- |
| 1 | `src/model/`：構成、語彙、教材を分離 | 文字の往復、出所、ID追加、形状が一致する |
| 2 | `src/model/transformer.js`（独立試作を移植。旧 `neural.js` は削除） | 複数層・ヘッド、因果性、対象マスク、旧重み保持が通る |
| 3 | `src/save.js`、操作調停の新設 | 保存失敗・中断で一組が維持され、二重適用しない |
| 4 | まとまり探しと結果データ | 空教材・再実行・満杯・初見文字・元会話の表示を確認する |
| 5 | `mindview.js`、`neural-view.js`、説明、素材 | 本とバインダーへ置換し、全入力・残差・層・ヘッドが追える |
| 6 | `items.js`、`stage.js`、作成画面 | ノート／勉強、アイテム／棚、停止復元、設定保存がつながる |
| 7 | チップUI・旧方式・途中コードの整理 | 残す計算機能を切り離したうえで旧導線を除去する |
| 8 | PC／スマホ確認とローカル提示 | 数値と演出の一致、操作、容量・速度を確認する |

新設モジュールは語彙、教材、操作調停、トレース閲覧を責務ごとに分ける。ファイル名は実装時に確定する。ビルド工程・フレームワーク・機械学習ライブラリは追加しない。

実装の検証は①モデルと保存の自動検査、②実トレースと表示の照合、③PC・スマホの通し操作、の順。公開はローカルでの見た目・動きの調整後に扱う。

## 10. 検証して確定する項目

| 項目 | 決め方 |
| --- | --- |
| 会話保存上限の単位・候補値、文字容量 | 原文・学習待ち・重み・直列化中の複製まで含む容量測定。最大の1会話も確認 |
| まとまり登録上限 | 文字数を独立に増やし、満杯後の文字追加と保存を検証。試作の総語彙1024をそのまま流用しない |
| 頻度のしきい値・一度の追加数 | 空・反復・重なり・同頻度・既登録・大きい教材で決定的な結果と時間を確認 |
| 新規重みの初期化 | 平均を第一候補に、旧数値保持・有限値・継続学習を確認。品質変化は許容する |
| 文字境界 | 結合文字・絵文字・異体字・改行で原文の往復とブラウザ間の一致を確認 |
| 学習とトレースの処理量 | 最大構成・最大文脈で停止応答・表示用メモリ・保存時間を測る |
| 温度設定 | 計算の抽選処理をチップから独立させる。利用者向け設定の存廃は未確定のまま残す |

将来のファイル交換は文章を介した相互推論と自分側の通常学習として接続する。今の段階で通信・重みの合体・複数セーブ管理画面を追加しない。
