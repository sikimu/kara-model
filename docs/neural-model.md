# 小さなニューラル言語モデル

2026-11-14更新。自己回帰Transformer型LLMの実際の学習・推論に対応した体験を目標とし、本・バインダー方式で実装した。構成・語彙・保存の仕様は [model-settings.md](model-settings.md)、実装の仮の値は [session-handoff.md](session-handoff.md) を参照。

## 実際のLLMに合わせる基準

- 文章をトークン列へ変換し、各トークンの表現を文脈と組み合わせて次のトークンを予測する。「1文字だけを学習してから複数文字の方式へ進級する」という独自の段階は設けない。
- トークンは必ずしも1文字でも1単語でもない。このゲームは書記素（1文字）から始め、机の勉強で「よく出る並び」をまとまりとして登録する。既存の番号と重みは保持する。[Tokenizers](https://huggingface.co/learn/llm-course/chapter2/4)
- 学習は正解の系列を使い、各位置でその先を見ずに次トークンを予測し、損失から重みを更新する。予測対象の正解を入力へ先に渡さない。[Causal language modeling](https://huggingface.co/docs/transformers/en/tasks/language_modeling)
- 推論は入力文脈を処理して次のトークンを選び、その結果を追加して繰り返す。KVキャッシュは未実装で、毎トークン窓内を再計算する。[How caching works](https://huggingface.co/docs/transformers/en/cache_explanation)
- Attentionで位置間の情報を参照し、位置ごとの変換や残差を経て次の予測を作る。部屋を回る動きは計算依存の説明であり、実機が文字1個ずつ物理的に処理するという意味ではない。[Attention Is All You Need](https://arxiv.org/abs/1706.03762)
- 大規模LLMとの違い（規模、事前学習・教師あり調整・選好学習の有無、バッチ学習、サブワード、キャッシュ）は説明の中で区別する。実LLMが利用中に自動で語彙を増やすとは説明しない。

## 現実装（`src/model/`）

- 構成は作成時に選ぶ。初期値は文脈128・48次元・3層・3ヘッド・MLP幅96（`config.js` の `PRESETS`）。選択肢は独立検証済みの組み合わせだけ。
- 対応表（`vocabulary.js`）: 目印9個（はじまり・おしまい・交代・あなた・コト・話す人1〜4）、文字（書記素、`Intl.Segmenter`）、まとまり（2つの番号の結合、追加順に適用）。番号は末尾追加のみ。
- Transformer（`transformer.js`）: 学習する位置埋め込み、各層で RMSNorm → 因果マスク付き多頭自己注意 → 残差 → RMSNorm → GELU MLP（幅 2d）→ 残差。出力の原本は V×D で語彙を末尾に足せる。原本は Float32、中間値と勾配は Float64。
- 学習（`model.js` `sleepAsync`）: 学習待ちの会話を系列にし、文脈窓に収まる窓へ分けて（重なった正解は1度だけ）、対象位置の交差エントロピーを平均して1系列ごとにSGD更新（学習率0.25、勾配ノルム1でクリップ、12周）。正解にするのはユーザーのお手本と招いた相手の発話とその直後の交代・おしまい。コトの生成文と話者の目印は文脈に入れるが正解にしない。
- 推論（`infer`）: 入力の未登録文字を登録してから `<bos> <user> 文 <turn> <assistant>` を文脈にし、最後の位置の確率で候補（文字とまとまり、おしまい＝eos+turn）を抽選。最大30トークン。原本は変わらない。
- 勉強（`study.js`）: 本に残っている会話（生成文を除く）で隣接する札の組を数え、2回以上の組を回数順に1つずつ登録（1回で最大4つ、6文字まで、登録上限まで）。新しい欄は構成元2つの平均。対応表と原本を一組で保存できたときだけ採用する。
- 保存（`save.js`）: `{formatVersion: 2, revision, config, limits, vocabulary, parameters(Base64 Float32), conversationBook, pendingLessons, progress}` を1つのキーに置く。

## 原本・バインダーと計算の対応

| 工程 | トレースに残す値 | 画面 |
| --- | --- | --- |
| ① | 窓内の全位置について、文字の本の行・順番の本の行・その和 | 札がページになりバインダーへ。最後の位置の3列の棒 |
| ②③ | 層・ヘッドごとの、最後の位置から見た見る割合・点・V の各位置の値・まぜた結果 | 札の下の棒が見る割合。ヘッドは切り替え |
| ④ | 層の入力・③の投影・残差 | 3列の棒（2層め以降は前の層の出力を足す） |
| ⑤ | 広げた数（MLP幅）・しぼった数・2回目の残差（層の出力） | 3列の棒 |
| ⑥ | 最後の層の出力・候補の点と確率 | 棒と候補の札 |
| 学習 | 周ごとの損失・当てっこ・各本の抜粋の前後・全パラメータの平均変化 | 原本を書き直して棚へ戻す。掲示板に損失 |

原本は文字の辞書だけではなく、各層の Q/K/V/O/F1/F2 と出力の本・バイアスを含む。部屋ごとに本を分けるのは表示上の整理で、各部屋が独立したモデルという意味ではない。バインダー（`inspector.js`）の見開きは、左が①で写した全位置のページ、右が最後の位置の現在の情報。原本は本棚から層ごとに開ける。

## 省略・簡略化

- 窓外のトークンは計算に使わず、ならべる部屋には束として残す。
- 推論は最後の位置の予測だけを使うが、計算は全位置に対して行っている（因果マスク）。
- 学習表示は1周分の更新をまとめ、各本の先頭24個または練習に出た2文字の行を抜粋する。全体は原本の本で確認する。
- `learned` 判定（学習前は無言）はゲーム上の制御で、一般のランダム初期化モデルでも確率の計算自体は可能である。

## 検証

- `node tools/check-neural.mjs`: 勾配の検算（全パラメータ群）、因果性、正解マスク、文字の登録、まとまりの追加（旧番号・重みの保持、旧候補の点の不変、継続学習、保存復元、上限）、記録と実計算の一致。
- `node tools/check-neural-view.mjs`: 説明文が構成（次元・層・ヘッド）と記録に一致し、モデルの値を変えないこと。
- `node tools/check.mjs` / `--mobile` / `--mind-preview`: 画面での通し操作。
